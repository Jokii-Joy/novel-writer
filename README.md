# 精神空间 · Mindspace

DeepSeek Harness 里的一体化小说写作插件：章节树、沉浸写作、AI 校对与一键排版、
导入导出（txt / md / docx / epub / pdf）、投稿向导与期刊库、收件箱、加密本地存档，
外加一个 Android 手机端，在同一个 Wi-Fi 下与桌面双向同步。

![书架与编辑器](docs/screenshots/final-01-canvas.png)

## 功能

- **写作**：可折叠章节树、沉浸模式（`F11` 或 `Ctrl/⌘+Shift+F` 进出）、打字机模式、粗光标、
  九套阅读主题、白天/黑夜；章节标题在稿纸上点一下就能改，首页「正在创作」直接标出正在写哪一章。
  默认只照亮**屏幕中间**那几行、上下其余淡去——**沉浸与非沉浸都一样**（书架开着时也一样，
  纱只盖纸面不盖桌面）。它锚在屏幕中间而不是跟着光标跑，所以一打开章节就到位；
  光标走出这条亮带时视口才轻轻挪一下，把它带回带子里。设置里可关，可调上下留几行。
  右下角一枚**写作工具圆钮**：收起时是一枚正红色的圆形按钮，静静贴在纸边；
  点开从上方长出**五个独立的按钮**（排 / 建 / 校 / 读 / 投），各是图标 + 完整名字，
  彼此之间留着 8px 的空、各长各的皮；悬停的那一枚铺一层品牌色薄雾。再点一次
  （或选中任一动作）就收回去。沉浸模式下更淡，但仍然在。
  五个按钮就是五个按钮，不是一整块板：每枚自己的底是纸色只掺 4% 墨、边是一根
  55% 的发丝线、下面一点浮影；没有卡片、没有尖角、没有分隔线、行尾也没有箭头，
  按钮之间是真的空出来的纸。**每枚按钮只有自己的名字那么宽**，右缘对齐圆钮、
  左缘随字参差——它不该为了整齐而拉成一样长。
  五枚排成**从下往上的一级级台阶**：越靠上越长、也略高一点点，右缘一律齐着圆钮，
  左缘一级一级退出去；台阶的长短完全由那一行的名字决定（四个字的同上同宽，
  三字、两字依次收窄），每一级留的余量都是同样多，谁也不多吃一口空白。
  名字从长到短往下排，所以顺序是 排 → 建 → 校 → 读 → 投：如果长度和台阶反着来，
  最长的那一级反而配最短的字，中间就会空出一大块。
  图标各占一格 26px 的圆角小方块，悬停时和这一枚一起亮起来。
  那条 8px 的缝是**画出来的**（按钮的形状上下各内缩 4px），行盒子本身首尾相接——
  指针落在缝里时命中的仍是相邻的按钮，不会掉进一个没反应的空档。
  整条坞没有任何「自己不属于按钮」的像素：容器不带内边距、不留行距、不画底色和描边，
  圆的形状、行的胶囊全部由按钮自己的伪元素画出来。这一点是被反复咬过的——容器只要有
  一圈属于它自己的内边距，鼠标停在那圈上就是箭头、点击也会被吞掉。没有开章时这些
  动作不会「静默失效」——点下去会明确告诉你「先打开一章」，而不是一声不响。
  如果哪天它又「点不动」，先看看屏幕右下角有没有别的程序的**置顶悬浮球**（托盘助手、
  下载工具、加速球）：那种球浮在整个桌面上，会先把光标和点击接走，插件这边的 CSS 再
  怎么改都赢不了。这不是假设——曾经有整整五轮修在这里空转，最后是用户在桌面上同一
  位置点出那颗球的菜单才真相大白。
- **读一遍**：把整本书铺成书页——没有光标、没有工具栏，方向键 / 滚轮 / 点左右半页翻页，
  `Esc` 回到刚才那一句。字号行高主题跟着写作设置走，版面容得下多少字就排多少页，不预设分页。
  **宽屏时对开两页**：屏幕够宽（可用宽度 ≥900px）就左右各一栏、中间一道装订线，像摊开的书；
  面板窄了自动退回单页，不需要手动切换——判据是这一页真的放不放得下两栏，不是某个模式开关。
  读的时候可以选中一段字画下划线、删除线或写一条批注，写作时也看得见，改过字它也跟着走。
  **文字只属于批注**：下划线说「这句好」、删除线说「这句要删」，两条线都不带字；
  一旦给一条线写了字，它就是批注了（同一句话不会同时是下划线和批注）。反过来把批注的字删空，
  它退回一条下划线。
  带批注的那条线在**右侧页边**配一枚小签，和它指向的那一行齐平——小签在页边空白里，
  永远不压字；签上写着这一章的第几条批注，鼠标移上去、或点开它，它指的那句会明显亮起来，
  同一行挂两条也分得清谁是谁。对开两页时，左页的签在左边、右页的签在右边（各贴自己那页的
  外缘）；回到单页，所有签都回到右侧。
  点小签或点那条线本身，就在点击处旁边浮出一张小便签（下划线和删除线只有「删除」，
  批注直接展开原文就地改）。批注**没有保存键**：字打进去就存，停一下就落库，
  点别处（任何地方）、Esc、滚动、翻页都会收起并把最后一句补上。翻页是横向滑过去的：
  正文轻轻淡一下、页边签先退场，没有「一个框在动」的感觉。
  写作时也能标注：拖选一段字，**按右键**，从「下划线 / 删除线 / 批注」里挑一个，点一下就地成线
  （选字不会再弹按钮条，纸面上也没有常驻的标记按钮；没选中字时右键仍是系统菜单）；
  点划过的字（或右键它）：下划线和删除线就在那一行旁边浮出**一个「删除」**，看完即撤，
  没有多余的引文和「知道了」；批注也只展开它那句话本身和「删除」——不再抄一遍划线内容。
  （要看要删在写作区，要改回「读一遍」）。同一段字只会有一条标注：重复划只会换类型，
  删一次就干净。
- **进度与设定**：状态栏带「今日 +N 字 · 连续 N 天」；目录树每章可标「修改中 / 已定稿」，
  设了目标字数就显示「1200/3000」、达标转绿；右键「章节信息」改状态、一句话简介与目标；
  写作区左上胶囊的「段落」给本章按行出一份目录，点一下滚过去；书的「⋯」菜单里是**设定集**
  （人物 / 地点 / 道具 / 设定，按书存），只给自己看，不进正文、不进导出。
- **版本**：每次切换章节或手动快照留一版，可以「对比当前」逐行看差异（增删高亮 + ±行数）再决定恢复。
- **外观**：九套主题之外，可以**跟随系统深浅色**——系统亮用哪套、暗用哪套各选一次，切系统主题即时生效。
- **AI**：AI 校对逐条给出修改建议；一键排版；模型选择与自动回退。
- **修改建议**：右下角坞里的那一栏通读整章，指出最值得改的地方（角度**可多选、也可以不选**——
  选了几颗就只看那几个角度，一颗不选就按输入框里的要求来；点角度只是改选择、不会开跑，
  选好了再点「开始审读」；**卡片边读边出现**，不必等整次请求结束）；
  **选中一段字**还会在指针旁边浮出一枚小钮，点开在正文右侧并排开一扇窗口，只针对这几个字给出**能直接
  替换的改法**——原文和改后左右对照（并逐字标出删了哪几个字、补了哪几个字），不用选模型、不用选角度；
  卡片一条条流式出现，不用等整段。每条下面有 **复制 / 替换到正文 / 再改一版**：替换是真正写进稿子、
  并且能一键撤销；「再改一版」把刚读到的那一版发回去，要一版明显不同的，可以一路迭代到满意。
  每条还能接受或拒绝；**接受只记账、不会替你改正文**，接受成功就从待处理列表移走、出现在
  下方「已接收」里（同一个地方改过两次以上会归成一组、用 ① ② ③ 标出先后），拒绝的直接丢弃。
  点「已接收」里任何一条，正文里对应那句会滚到视线中间并高亮；同一段字再打开**不会重复计费**
  （结果缓存在本地，页脚会标「上次的结果」）。
  栏底还有 **粘贴其他 AI 的建议**：把面板里给的格式（原文 / 问题 / 理由 / 建议 / 改后，或一个 JSON 数组）
  贴进来，导入的卡片与模型给出的完全同构——同样高亮、接受 / 拒绝、复制 / 替换 / 撤销；原文按当前章节
  定位，找不到的会标「定位不到」，不会乱指。点「复制全文与全部问题」会连**本章全文和已有问题**一起复制，
  直接发给另一个 AI 即可；桌面版由宿主直接写入系统剪贴板，不依赖浏览器权限。
  这些记录存在本机 IndexedDB，随备份走，不上传。
- **稿件**：导入 txt / md / docx / epub 自动分章；导出 txt / md / docx / epub / pdf。
- **投稿**：三步投稿向导，内置 79 家文学期刊库（可增删改），按体裁/字数/风格推荐；
  投稿记录跟着书走，改名后显示「现名（投稿时：旧名）」。
- **邮件**：SMTP 发信、IMAP 收件箱，直接在插件里读投稿回信。默认要求 TLS 并校验证书；
  证书校验失败或服务器不提供 STARTTLS 时会中止（避免授权码被中间人截走），
  确认是公司代理 / 可信内网中继时，可在设置里打开两个标着「不推荐」的开关。
- **存档**：本地 IndexedDB + 可选加密（PBKDF2 + AES-256-GCM），版本历史与回收站；
  保存到文件夹时书名改动会覆盖旧文件，不会越攒越多；**只重写改动过的那几本书**，
  一百本书也不会每次空闲都写一遍。文件夹快照里带着书、便签、**标注、设定集、已接收建议**与
  投稿记录；**恢复不会清空快照里没有的数据**（版本历史与回收站原样保留），
  要把它们搬到另一台机器请用设置里的「导出 JSON / 恢复」。
  **重装宿主也不会再丢密码与设置**：密码的校验值、主题字号与面板布局会被备份在
  `DSH_HOME/novel-writer/client-state.json`（不含密码本身），下次打开只要重输一遍密码即可解锁。
- **手机**：Android App 与桌面局域网同步（配对码 / 扫码），断网改动合并时不丢书；
  **配对完就自动同步**，不用再找按钮——书架状态每 5 秒刷新一次「自动同步已开启 · 刚刚同步过」，
  右边的「立即同步」只在想亲眼看着它跑一次时才用；
  手机改过的一段同步过来时，电脑端的光标留在原处、视口跟到改的那一句，不会跳到文末；
  写作页带一条中文标点符号条（Tab、成对引号、书名号、破折号、省略号…），打字不用翻符号页；
  编辑器 header 有 **修改建议**：整章或选中一段交给桌面上的编辑模型，回来是一页「每段下方挂一段
  只读意见」——引文、问题、判断依据、怎么改、示例，正文本身就是输入框，照着意见改自己的句子
  （模型和密钥都留在电脑上，手机不持有，建议也不写进正文）。
  点「修改建议」先弹一张开跑单：**选模型**（拉电脑上的可用列表，默认跟电脑当前的选择走）、
  **选关注点**（全部 / 节奏 / 语言 / 视角 / 画面 / 对话 / 结构 / 人物 / 逻辑 / 情绪 / 冗余）、
  **写一句额外要求**（如「别动对话，只看结尾」）；选中的模型只记在这台手机上。

## 安装

插件包目录即仓库根。在 DSH 里执行：

```
plugin_manager action=install_bundle target=<本仓库绝对路径>
```

安装后左侧栏出现书本图标，点击进入「精神空间」主面板。校验 Host 是否就绪
（`dsh web` 的端口每次启动都会变）：

```bash
curl http://127.0.0.1:<web端口>/novel-writer/api/ping
# {"ok":true,"data":{"name":"novel-writer","version":"1.6.16",...}}
```

改 Host 代码后要**重载插件**（Node 模块已缓存）：

```
plugin_manager action=set_plugin target=include:novel-writer enabled=false
plugin_manager action=set_plugin target=include:novel-writer enabled=true
```

只改客户端则重建产物，刷新页面即可：

```bash
node scripts/build-client.mjs    # client/src/*.js → client/client.js（含加载闸门）
```

## 手机端

APK 在 [`dist/精神空间.apk`](dist/精神空间.apk)（约 0.54 MB，Android 7.0+，无需 Gradle 构建）。
源码在 `app/`，用 `node tools/build-apk.mjs` 重新打包。当前 `versionCode 2 / versionName 1.1.0`，
直接覆盖安装即可升级（同一个 debug 签名，数据与配对记录都保留）。

配对：桌面「设置 → 手机同步」生成地址与配对码 → 手机「配对」里手填（扫码为备选）。
**配对成功就开始自动同步**：应用起动、回到书架、每次编辑之后都会各推一次，后台服务每 45 秒再跑一轮；
书架顶部写的是「自动同步已开启 · 刚刚同步过」而不是一个需要你去按的按钮。
同步走局域网 HTTP，端口 41288，UDP 41287 发现（双向：桌面每 10 秒广播一次，手机也发
`role:'probe'` 探针、桌面立刻单播应答，所以点一次「立即同步」就能找到电脑，不必反复按）。
正文在手机上以明文存放，桌面侧的同步缓存仍用本机密钥加密。

修改建议：手机上的「修改建议」不是在本机跑模型，而是带着配对凭据请求桌面的
`POST /nw/v1/ai/revise`（HMAC 与同步同款、单次 2 万字、同一时间只跑一条；`ai/proofread` 仍保留给
逐字校对用）。点开先是一张开跑单：模型走 `POST /nw/v1/ai/models` 拉电脑上的可用列表（第一项永远是
「电脑当前的默认模型」，选过的记在本机，不改电脑自己的选择），关注点与「额外要求」直接对应桌面对话框
里的那两个下拉与输入框；选中的模型不回话时会自动退回电脑默认模型并提示一次。

结果页：整章按行拆成段落，**每段的意见卡片就挂在这一段下面**，卡片是只读的（能长按复制，不能输入），
段落本身可以直接改字；对不上原文的意见收在页尾。因此**电脑得开着、插件得启用、模型得可用**。这一页
按段落编辑，跨段落选区和「把两段并成一段」做不到，回写作页仍是整块正文。

等待时是一张卡片：进度条、「正在读第 2 / 5 批…」、已用秒数。点卡片外面不会关；按返回只是把它收起来，
**整次运行在后台服务里继续**——回手机首页、退回书架、锁屏都不影响。页面上会留一条「正在读这一章 ·
第 2 / 5 批」的条，点它把卡片叫回来。**只有右上角 ✕ 会真的断开请求、停止这次模型调用**。跑完通知栏
留一条「建议已就绪」，回到那一章会自动打开建议页；建议按章存在本机（最多 12 章），编辑器里多一条
「查看上次的修改建议」，再看不花第二次钱。长章要有耐心——一万六千字以内整章一次发完，
更长才分批；一次请求通常几十秒到两分钟（换更快的模型会明显快）。把 App 从最近任务里划掉或强行停止会中断，这是系统行为，前台服务也拦不住。

需要先重载插件让宿主
拿到新端点：

```
plugin_manager action=set_plugin target=include:novel-writer enabled=false
plugin_manager action=set_plugin target=include:novel-writer enabled=true
```

## 开发

```bash
node scripts/verify-host.mjs     # 离线宿主测试（不需要运行中的 DSH）
node scripts/verify-lan-ai.mjs   # 手机 AI 端点的鉴权与能力声明（6 项，不需要真机）
node scripts/verify-docs.mjs     # 导入导出与 docx/epub 排版断言
node tools/build-apk.mjs         # 重打 APK（工具链在 .tools/android/）
bash tools/build-apk.sh          # 同一套五步的 bash 版（Node 的管道 spawn 被沙箱拒时用）
```

> 构建脚本对路径有要求：`aapt2` 在 Windows 上读不了含中文的**绝对**路径（本仓库在 `编码区/` 下），
> 所以 `build-apk.mjs` 给它的一律是相对路径；它也不能用管道 stdio 起子进程（沙箱里直接 EPERM），
> 因此 `run()` 用 `stdio: 'inherit'`，子进程的输出直接进控制台。

- 运行时零第三方依赖：Host 只用 Node 内置模块，Client 只用宿主提供的 `react` 与主题 token。
- 入口：`index.js`（Host）+ `client/client.js`（浏览器，由 `client/src/*.js` 按文件名拼接）。
- 接口：`/novel-writer/api/*`，统一 `{ok, data|error}`，方法表见 `docs/CONTRACT.md`。
- 目录说明与逐轮改动记录见 [`docs/CHANGELOG.md`](docs/CHANGELOG.md)。

失败会重试并记在 `.tools/push.log`。配置见 `docs/CHANGELOG.md` 的「上传到 GitHub」一节。
